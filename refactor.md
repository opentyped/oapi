## Rejected or deferred (with reasons)

- **Vite watcher removal** — load-bearing: dependencies Vite ignores, symlink recovery, build-watch mode, checked-source consistency. Needs behavioral equivalence, not fewer lines.
- **Hash-suffix naming "violation"** — AGENTS.md's no-hash rule governs operation IDs only; internal specialization names are out of scope. (Truncation 10-vs-16 note: documentation only.)
- **Traversal-budget unification** — different algorithms legitimately need different limits; matching numbers is busywork.
- **`npm run build --workspaces`** — workspaces is a glob expanding alphabetically (compiler before openapi); the explicit scripts enforce the real dependency order.
- **One-liner wrappers** — trailing-slash strip, `errorMessage`, callable predicate, `relativePosixPath`, `operationName` fallbacks: self-evident one-liners; helpers add navigation, not meaning.
- **Type-level seams** — media-key selection (`contract.ts` ↔ `response.ts`), method-set generation: different predicates by design; document, don't unify.
- **`renameAll` direction gap** — intentional Serde-style rules; extending conversion is a feature decision, not a refactor.
- **Annotation constants in compiler** — violates dependency direction (schema can't import compiler); fixed by item 10's openapi home.

## Test-infra findings (pass 34)

- **Config ignore drift (definite bug):** the harness's per-test temp prefix was renamed `.golden-` → `.contract-` (`tests/golden.test.ts:28`), but `eslint.config.mjs:192` still ignores only `tests/.golden-*/**` and `.prettierignore:8` only `tests/.golden-*/`. While any suite run is in flight, its own transient dirs are linted/formatted → the recurring ENOENT races. Fix: update both entries to the `.contract-*` prefix (owner: config files, outside goal write scope).
- **Flake correlation (two transient full-run failures — 432, 331 — both pass in isolation/re-runs):** both coincided with external in-place fixture rewrites (`331`'s `openapi.json` regenerated 13:53, flaked ~14:31) and a concurrently running second suite process (`node --test-concurrency=0 --heap-prof-interval=…`). The suite's own isolation (unique `mkdtemp` copies per test) is sound; the mismatch risk is a torn `cp(fixture, root)` when external tooling rewrites fixture files mid-copy. Optional hardening: harness copies to a unique dir then snapshots file contents before compiling, or the regeneration tool writes temp+rename.
